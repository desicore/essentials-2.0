## What is Just-In-Time provisioning and how to set it up

Platform Notice: Cloud Only - This article only applies to Atlassian apps on the [cloud platform](https://confluence.atlassian.com/display/Cloud/Compare+Atlassian+cloud+vs+server).

## Summary

Just-In-Time (JIT) provisioning is a mechanism to automate the creation of user accounts in Atlassian applications when they log in for the first time through SAML SSO.

The data required to provision the user comes from the identity provider (IdP), so it eliminates the need for manual user provisioning and saves time and effort.

Key aspects of JIT provisioning include:

- **Efficiency**: User accounts are created only when needed.
- **Manageability**: Accounts with the verified domain will be provisioned and will become managed accounts.
- **Automation**: User attributes such as first name, last name, and email are automatically updated during the login process.

## Solution

### Prerequisites

- [Atlassian Guard subscription](https://support.atlassian.com/security-and-access-policies/docs/understand-atlassian-guard/)
- [SAML SSO is configured](https://support.atlassian.com/security-and-access-policies/docs/configure-saml-single-sign-on-with-an-identity-provider/) with your IdP

### Configuration

In order to enable JIT provisioning for your managed accounts, you need to configure all of the following:

1. Make sure the [claim setting is Automatic](https://support.atlassian.com/user-management/docs/verify-a-domain-to-manage-accounts/#Claim-account-settings). Additionally, ensure the 'Application username format' and 'Primary email attribute' in your IdP configuration are consistent with the email addresses in Atlassian accounts to avoid mismatches and potential duplicate account creation.

	⚠️ *If the domain is claimed in multiple Atlassian organisations, make sure which organisation should have the automatic claim setting before making any changes.*
2. [Link domains to your identity provider directory](https://support.atlassian.com/provisioning-users/docs/link-domains/)
	Associate your verified domain with the IdP config where SAML SSO is configured for JIT Provisioning.
3. [Enforce SAML single sign-on on a default authentication policy](https://support.atlassian.com/security-and-access-policies/docs/understand-authentication-policies/#What-is-a-default-authentication-policy)
	The **default** authentication policy associated with the IdP must have Single Sign-On (SSO) enforcement enabled.
