Synthesis

Read this first. Sections Q1–Q6 below hold the evidence cards; every product and reference id named here is in the report. Ids are shortened to their first block (for example mobbin:3135010e).

Top examples

  1. The Leap (Refero, refero:4564) — one flow from recipient segment to confirmation to live open/click stats: the whole loop a course announcement needs, in eight steps.
  2. Google Classroom (Refero, refero:19605564) — the audience dropdown ("For · All students") sits on the composer itself; the canonical LMS composer.
  3. beehiiv (Mobbin, mobbin:748e794e) — one post object with Post / Email / Website tabs and a per-channel recipient summary before Send.
  4. Basecamp (Mobbin, mobbin:0bc24c79) — separates "who should see this" from "who gets notified" inside one composer.
  5. Mural (Mobbin, mobbin:836e980f) — a single access panel with access level, visitor-link level, password, timezone-stamped expiry and Reset link.
  6. Navan (Mobbin, mobbin:9d8af34f) — per-person status table where you select the non-responders and "Send a reminder" without leaving it.
  7. SchoolAI (Mobbin, mobbin:3135010e) — the only complete LMS hand-off: Export → permission → class picker → "Exported to Google Classroom!".
  8. Microsoft Teams (Mobbin, mobbin:88ad5199) — "Announcement" is a distinct post type with a bold title and replies attached; learners can tell it from chatter.

What the best apps do differently

  • They separate visibility from notification. Basecamp asks "who should see this?" and, separately, "when I post this, notify…" (mobbin:0bc24c79); beehiiv reconciles channels into a per-channel recipient count before Send (mobbin:748e794e). Substack collapses email and push into one default-on toggle (mobbin:a7ebc4ec), the simplest version of the same idea. Nobody in the set exposes an LMS as a channel inside the composer.
  • Scheduling is a property of the send button, not a feature. Slack's send dropdown with presets (mobbin:fd356e91), Whop's inline popover (mobbin:16eb85ed), Kit's send-time field that defaults to now (mobbin:f722d4bb), LinkedIn's clock icon (refero:863). Only Confluence adds an end date (mobbin:fcc604e7), the closest thing to "show this until the session".
  • Audience targeting is coarser than expected. Google Classroom offers "All students" or a selection (refero:19605564), Teachable everyone / course / individual (refero:9617), The Leap named segments (refero:4564). ClassDojo has no audience control at all because the class is the audience (mobbin:53e9bdad).
  • Feedback only matters when it is per person and has an action next to it. Navan selects non-responders and reminds them from the same table (mobbin:9d8af34f); Superhuman shows who opened, on which device, when, inline on the thread (mobbin:ba56c2de); HoneyBook branches the follow-up on "viewed within 1 day" (mobbin:8afb0d65); Docusign configures reminder cadence (mobbin:e4a526c1). Aggregate dashboards (HubSpot mobbin:5814d24c, Dub refero:2fe44823) and Square's empty "Seen by" column (mobbin:1c8c3422) give a course manager nothing to act on.
  • Link controls converge on one panel with five questions. Who can open, at what level, until when, with which password, how to revoke: Mural (mobbin:836e980f), Proton (mobbin:ef4fcd7f), Notion with relative presets resolved to a date (mobbin:cfca14fb). Loom is the only one that puts view tracking beside the share (refero:1242). ClickUp (mobbin:7f248abd) is the counter-example: expiry defaults to Never, no level, revoke is Unpublish.
  • The LMS hand-off maps to a specific class and confirms. SchoolAI is the only complete example (mobbin:3135010e). Course platforms treat publishing as the send and never hand off (Kajabi mobbin:9aa981d2); generic connectors stop at authorization (Craft mobbin:e9079303, Cofounder mobbin:7897406d, counter-example).
  • On the learner side, announcements get their own type or place. Teams' "Announcement" post type (mobbin:88ad5199), Circle's separate Announcements space (mobbin:c1b1c3ad), ClassDojo's teacher-only Pin (mobbin:3edf67a5); unread state aggregated centrally in Slack Activity (mobbin:8e65f9c9); channel preference per category in Spotify (refero:471b8f0c). Coursera's undifferentiated Latest list is the counter-example (mobbin:36db9592).

Best practices top companies converge on

  • One composer for announcements and material sends; the post in the portal is the record, channels (email, push, link, LMS) are how people hear about it.
  • Ask two questions, not one: who can see this (course / group / individuals) and who gets notified now.
  • Put "send now / schedule" on the send button with presets; add an optional end date for time-boxed material.
  • Attach materials by reference from the course library, not by re-upload (no product in the set does this; it is the gap Essentials can fill).
  • Give the shareable link one panel: who, level, expiry (relative presets resolved to a date), password, revoke; show opens next to the link.
  • Report delivery per person with an action beside it (remind non-openers, optionally automatic before the session); aggregate counts are secondary.
  • For the LMS hand-off: say what will be sent, map to one specific course, confirm with a toast, and keep the link back.
  • On the learner side: a distinct announcement type, pinnable, with attachments and replies inline, and a central unread inbox that agrees with email.

Open questions for Essentials 2.0

  • Audience unit. The set targets by segment or course. For a simulation course the natural units are the course roster, the learner groups from sub-module 04, and the session cohort from 06; faculty and observers are a fourth audience nobody in the set models.
  • Materials by reference. Every composer uploads. If materials live in sub-module 02, an announcement should link to the library item, inherit its access, and show whether it is already released; no reference shows this.
  • Portal as source of truth. If the Learner Portal feed is the record, email and push are notifications of the same post, and the shareable link is a login-free view of it. That ties directly to the access-sharing module (magic links, time-boxed access); the link controls in Q3 should reuse those rules rather than add a second permission system.
  • Canvas hand-off object. SchoolAI sends a document to one class. For Canvas the open questions are what object is created (announcement, module item, or a link back to the portal), how an Essentials course maps to a Canvas course when they differ, what happens on edit after send, and whether the learner then has two places to look. No reference shows edit-after-send or re-sync.
  • "Seen" in education. Superhuman-style per-person opens are useful before a simulation (did they read the pre-brief?) but may feel like surveillance to learners. Whether reminders are manual (Navan) or automatic before the session (Docusign / HoneyBook) is a product decision, not a pattern the set settles.
  • Scheduling against the session. Products schedule by date/time. Essentials could schedule relative to a session ("two days before", "after debrief"), which none of the references model.
