Summary of findings

Read this first. Sections Q1–Q6 below hold the example cards; every product and short id named here is in the report. Ids are shortened to their first block (for example mobbin:3135010e).

Top examples

  1. The Leap (Refero, refero:4564) runs one flow from recipient segment to confirmation to live open and click stats. That is the whole loop a course announcement needs, in eight steps.
  2. Google Classroom (Refero, refero:19605564) puts the audience dropdown ("For · All students") on the message editor itself. It is the clearest LMS message editor in the set.
  3. beehiiv (Mobbin, mobbin:748e794e) keeps one post with Post, Email and Website tabs and a per-channel recipient summary before Send.
  4. Basecamp (Mobbin, mobbin:0bc24c79) separates "who should see this" from "who gets notified" inside one message editor.
  5. Mural (Mobbin, mobbin:836e980f) puts access level, visitor-link level, password, timezone-stamped expiry and Reset link in a single access panel.
  6. Navan (Mobbin, mobbin:9d8af34f) shows a per-person status table where you select the non-responders and "Send a reminder" without leaving it.
  7. SchoolAI (Mobbin, mobbin:3135010e) is the only complete LMS hand-off: Export, then permission, then class picker, then "Exported to Google Classroom!".
  8. Microsoft Teams (Mobbin, mobbin:88ad5199) makes "Announcement" a distinct post type with a bold title and replies attached, so learners can tell it apart from ordinary peer posts.

What the best products do differently

  • They separate visibility from notification. Basecamp asks "who should see this?" and, separately, "when I post this, notify…" (mobbin:0bc24c79). beehiiv turns the channels into a per-channel recipient count before Send (mobbin:748e794e). Substack combines email and push in one switch that is on by default (mobbin:a7ebc4ec), the simplest version of the same idea. Nobody in the set offers an LMS as a channel inside the message editor.
  • Scheduling is part of the send button, not a separate feature. Slack uses a send menu with presets (mobbin:fd356e91). Whop uses an inline calendar menu (mobbin:16eb85ed). Kit uses a send-time field that defaults to now (mobbin:f722d4bb). LinkedIn uses a clock icon (refero:863). Only Confluence adds an end date (mobbin:fcc604e7), the closest thing to "show this until the session".
  • Audience targeting is less detailed than expected. Google Classroom offers "All students" or a selection (refero:19605564). Teachable offers everyone, course or individual (refero:9617). The Leap uses named segments (refero:4564). ClassDojo has no audience control at all because the class is the audience (mobbin:53e9bdad).
  • Feedback only matters when it is per person and has an action next to it. Navan selects non-responders and reminds them from the same table (mobbin:9d8af34f). Superhuman shows who opened, on which device, when, on the thread (mobbin:ba56c2de). HoneyBook branches the follow-up on "viewed within 1 day" (mobbin:8afb0d65). Docusign sets reminder timing (mobbin:e4a526c1). Dashboards that only show totals (HubSpot mobbin:5814d24c, Dub refero:2fe44823) and Square's empty "Seen by" column (mobbin:1c8c3422) give a course manager nothing to act on.
  • Products put the link controls in one panel that answers five questions. Who can open, at what level, until when, with which password, and how to revoke. Mural (mobbin:836e980f), Proton (mobbin:ef4fcd7f), and Notion with relative presets turned into a date (mobbin:cfca14fb) all show that panel. Loom is the only one that puts view tracking beside the share (refero:1242). ClickUp (mobbin:7f248abd) is the weak example: expiry defaults to Never, no level, and revoke is Unpublish.
  • The LMS hand-off maps to a specific class and confirms. SchoolAI is the only complete example (mobbin:3135010e). Course platforms treat publishing as the send and never hand off (Kajabi mobbin:9aa981d2). Generic connectors stop at authorization (Craft mobbin:e9079303, Cofounder mobbin:7897406d, a weak example).
  • On the learner side, announcements get their own type or place. Teams uses an "Announcement" post type (mobbin:88ad5199). Circle has a separate Announcements space (mobbin:c1b1c3ad). ClassDojo has a teacher-only Pin (mobbin:3edf67a5). Unread items gather centrally in Slack Activity (mobbin:8e65f9c9). Channel preference per category appears in Spotify (refero:471b8f0c). Coursera's mixed Latest list is the weak example (mobbin:36db9592).

What the leading products have in common

  • Use one message editor for both announcements and sending materials. Keep the post in the portal as the record; use channels (email, push, link, LMS) to tell people about it.
  • Ask two questions, not one: who can see this (course, group or individuals) and who gets notified now.
  • Put "send now / schedule" on the send button with presets. Add an optional end date for material that is open only for a set period.
  • Attach materials by pointing at the course library, not by uploading again (no product in the set does this; it is the gap Essentials can fill).
  • Put the shareable link controls in one panel that covers who, level, expiry (relative presets turned into a date), password and revoke. Show opens next to the link.
  • Report delivery per person with an action beside it (remind non-openers, optionally automatic before the session). Totals come second.
  • For the LMS hand-off, say what will be sent, map it to one specific course, confirm with a short message, and keep the link back.
  • On the learner side, give announcements a distinct type that can be pinned. Keep attachments and replies in the same place, and keep a central unread inbox that agrees with email.

Open questions for Essentials 2.0

  • What should count as an audience? The set targets by segment or course. For a simulation course the natural units are the course class list, the learner groups from sub-module 04, and the group attending a session from 06. Faculty and observers are a fourth audience nobody in the set models.
  • How should materials attach by reference? Every message editor uploads. If materials live in sub-module 02, an announcement should link to the library item, inherit its access, and show whether it is already released. No example shows this.
  • Should the portal be the main record? If the Learner Portal feed is the record, email and push are notifications of the same post, and the shareable link is a login-free view of it. That ties directly to the access-sharing module (sign-in links sent by email, access open only for a set period). The link controls in Q3 should reuse those rules rather than add a second permission system.
  • What Canvas item is created on hand-off? SchoolAI sends a document to one class. For Canvas the open questions include whether that item is an announcement, a module item, or a link back to the portal. How does an Essentials course map to a Canvas course when they differ? What happens on edit after send, and does the learner then have two places to look? No example shows edit-after-send or syncing again later.
  • How should "seen" work in education? Per-person opens like Superhuman are useful before a simulation (did they read the pre-brief?) but may feel like surveillance to learners. Whether reminders are manual (Navan) or automatic before the session (Docusign / HoneyBook) is a product decision, not a pattern the set settles.
  • Can scheduling run against the session? Products schedule by date and time. Essentials could schedule relative to a session ("two days before", "after debrief"), which none of the examples model.
