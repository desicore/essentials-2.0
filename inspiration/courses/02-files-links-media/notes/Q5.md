# Q5 — Visibility controls

**Squarespace** gives the clearest state model. The course rail labels lessons **DRAFT** or **SCHEDULED**, and the preview header repeats the state. The sampled flow is: select the lesson → **Set status** → **Scheduled** from **Draft / Published / Scheduled** → set date and time → **Save**. [mobbin:816b6484-5d04-4ef2-8a8b-2691f365fb1b]

**Teachable** separates release timing from publication. Lesson rows have **Publish**, while a section-level **Drip** controls availability. The sampled flow is: open drip → keep **Days after enrollment** → enter `1` → **Save** → **Activate drip**. The section gains an availability summary; the panel offers an optional email and UTC/local-time note. A companion frame also offers specific-date release. Activating drip is not shown to publish lessons. [mobbin:6739ae23-f32d-4706-9e4b-a07c9a056605] [mobbin:6f84d500-27bc-4a9c-9bf9-04e5f525e5f3]

**Kajabi** places a **Status** card beside lesson details, with radio choices **Draft** and **Published**, then a page-level **Save**. It is a strong example of an obvious binary state, but this frame shows neither scheduling nor group targeting. [mobbin:8f6d425a-cfdc-4b2a-a100-6ec7b5e4fcd4]

**Podia** exposes visibility through a row and overflow menu: find **Hidden** → open the kebab → **Set as visible** → verify **Hidden** disappears. Another section says **Delayed 1 day**, but this flow does not configure it. This is the counterexample candidate: the command is buried and the resulting visible state has no positive label. [mobbin:79259c68-06d8-411f-b63f-4d026338d2fe]

Across these samples, draft/publish and scheduled release are distinct concepts. No retained Q5 evidence demonstrates per-group visibility, so publishing must not be interpreted as group access.
