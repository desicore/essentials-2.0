# Q1 — Event creation surface: inline in course vs. global calendar with course tag

## Per-product observed answer

- **Acuity Scheduling** (`refero:9859`) — global catalog pattern. Flow: Appointment Types (global list) → "New Type of Class" (name/duration/price/room) → separately "Offer Class" opens a modal to set date/time and recurrence. Defining the reusable type and scheduling an instance are two distinct global-context steps; no course object.
- **Calendly** (`refero:df769788...`) — global. "Scheduled events" dashboard lists all events across event types with one global "+ Create" button; no project/course scoping visible.
- **Circle** (`mobbin:b360aa69`, `mobbin:f92f2d5a`) — mixed/ambiguous. The "Create event" form (`b360aa69`) opens with the top-nav "Events" tab highlighted (not "Courses"), suggesting it's a global Events surface, not a per-course modal — despite the reference's own take calling it inline. The companion flow (`f92f2d5a`) is genuinely inline: creating a "Scheduled" course space, naming it, and adding a Lessons section with per-lesson drip dates — but this is course *content* scheduling, not a bookable "event" with room/attendee fields.
- **Kajabi** — both patterns coexist in one product. Sessions inline under a specific Coaching product (`mobbin:1680974d`, breadcrumb Products/Coaching/Designers, "Schedule session" button, Session 1/2/3 list) vs. a separate "Create an event" form (`mobbin:64f56885`) reached via the left nav under **Marketing → Events** (breadcrumb "Events / New Event") — a global marketing calendar unrelated to any product/course. The coaching-session flow (`mobbin:c497ddd0`) confirms the inline path end to end.
- **Luma** (`refero:1843`) — global-calendar-with-tag. Global "Events" tab, empty state "No Upcoming Events" → Create Event opens a form that starts "Create under [Personal Calendar ▾]" — the calendar is a pickable/creatable container, i.e. a tag applied at creation.
- **TravelPerk** (`refero:5222`) — global. Persistent top-nav "Events" item; "Create an event" form has no project/trip association field visible in the shown steps.
- **Microsoft Teams** (`mobbin:30fee836`) — generic calendar meeting form (attendees, recurrence); no course/space concept present, weak evidence for this axis.
- **Preply** (`mobbin:5094f489`) — inline "Schedule lesson" button sits within "My lessons," but Preply has no course container (1:1 tutoring), so it only weakly supports "inline in course."
- **Zoom** (`mobbin:715206de`) — generic scheduler, no course/project context; not informative for this axis.

## What is distinctive

The clearest signal is Acuity/Luma/TravelPerk's shared move: separate the *reusable definition* (type, calendar, or global list) from the *act of scheduling an instance*. Kajabi is the most directly relevant because it shows a single product doing both — genuine inline session scheduling under a course-like object, and a fully separate global marketing-events calendar with no course link.

## Candidate counter-example

`refero:023aed7b` (Understory, tagged Q4 not Q1) shows a centered create/edit modal with no visible course/experience or calendar-tag field — but it's off-topic for Q1. Within Q1 itself, the best counter-example is **Circle's `mobbin:b360aa69`**: its own "take" claims inline-in-course, but the screenshot's active nav tab is "Events," contradicting that framing and instead illustrating the global-with-tag side.

## Evidence gaps

No reference shows an instructor picking "which course" from inside a create-event form (a course-tag field analogous to Luma's calendar picker, applied to an education/course product). No reference shows the reverse: a course page listing events that were created from a global calendar. Kajabi's two flows are the closest approximation but aren't directly linked.
