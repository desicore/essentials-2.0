# Q3 — Levels / rubric definition (numeric, descriptive, checklist)

## Evidence by product

- **Google Classroom — direct rubric builder.** `refero:239a7ddc-e5ed-4209-87dd-f329502b2271` shows “Design Thinking,” a **Use scoring** toggle, criterion title and description fields, a required point value (10), level title and description fields, controls to add another level, **Add a criterion**, sorting, and **Save**. This combines numeric and descriptive definitions in one editable structure. `refero:fd8e5fc8-d22d-4b80-ad7d-83c457db08ef` shows the same builder with the criterion worth 1 point, confirming that point values are editable not fixed. The visible composition is criterion → one or more levels → title/description/points; no checklist scoring or rubric versioning is shown.

- **Codecademy — progress display, not proficiency calibration.** `mobbin:d5c43b15-4d4b-4c10-9eaf-33d1e9533e44` shows “Skills tracking / HTML & CSS,” skill sets, skills represented by percentage boxes, and a **Subskills** drawer. Subskills carry 0% values; one row is checked, and the drawer links it to two “Builds toward…” skill sets with **Learn** and **Evaluate** actions. The image does not define named proficiency levels, performance descriptions, thresholds, or a rubric. Corrected caption: **“HTML & CSS skill-tracking dashboard with subskill completion percentages and Learn/Evaluate actions.”** Its distinctive contribution is decomposition and roll-up, not level authoring.

- **Visible — adjacent self-rating questionnaire.** `mobbin:9d4ec3e3-b07c-44ea-bc93-6d661226d178` lists daily activities, each with a chosen number (3 or 5) and a sentence such as “This rarely affects other activities,” followed by **Submit and calculate score**. It demonstrates numeric responses paired with human-readable anchors, but the screen neither defines nor edits those anchors. Corrected caption: **“Health-impact questionnaire with numeric responses and fixed descriptive interpretations.”**

## Flow and fit for Essentials 2.0

Only Google Classroom exposes a stepwise authoring pattern: name rubric → enable scoring → define criterion → add level title/description/points → add levels or criteria → save. This is the closest model for competency rubrics used across simulation scenarios, events, and reporting. Numeric scoring alone does not establish a calibrated rubric; checklist criteria and level versioning remain unsupported in this evidence set.

**Candidate counterexample:** Visible (`mobbin:9d4ec3e3-b07c-44ea-bc93-6d661226d178`) looks rubric-like because numbers have prose beside them, yet it is a respondent-facing health score form rather than an instructor-defined competency scale.
