# Q3 — Reuse across courses

**Canva** is the strongest direct library-to-course example. The sampled flow goes: course → **Add new** → **Choose design** → browse **Your projects** → open a project → select a design → **Copy to course** or **Move**. The final course view shows the presentations as ordered activities with resource type and access indicators. This demonstrates reuse of existing library content and makes copy-versus-move explicit. It does not show whether copied content remains linked, whether edits propagate, or one source serving multiple courses. [mobbin:bf1ec8aa-8666-4c94-acf3-5bb1db523411]

**Dropbox** offers the central repository analogue: persistent **All files** and **Shared** navigation, shared/team folders, **Upload or drop**, **Create folder**, search, Recents and Starred. Unlike Canva, this frame does not show selecting content from within a course or attaching it. [mobbin:389bb479-d3e5-4301-a2fa-af842ae2ee4b]

**Podia** and **Teachable** supply the placement contrast: Podia uploads a file into the current course section; Teachable adds a PDF inside a lesson. Neither flow proves a silo, because the captures do not establish whether uploaded assets also enter a reusable library. [mobbin:30a1432c-f8fd-4f5f-a026-53b0744635b2] [mobbin:fc5a2e31-b68a-4560-adbd-64534e99d8c6]

**Distinctive difference:** Canva names the reuse operation; Dropbox names storage locations; Podia and Teachable emphasize course placement. Dropbox is the candidate counter-example to treating a central file list as proof of a complete reuse workflow, rather than evidence of a missing product feature.

For Essentials, the unresolved decisions are live reference versus copy, pinned versions, edit propagation, asset ownership and where-used checks before replacing or deleting a file.
