# Q2 — Channel choice and one composer vs many features

## Per product

- **Basecamp** `mobbin:0bc24c79-1906-420b-8c71-4c4c9fada060`: single message-board composer (title + rich text) → inline "Who should see this?" (team-only vs allow client) → inline "When I post this, notify…" (only requester / everyone I select / no one) → Post button. One composer, no separate email/push/link controls — channel is implicitly "in-app post" with a scoped notify list.
- **beehiiv** `mobbin:748e794e-69b4-4b84-81e8-eb81c5e32f85`: one post object with top-level tabs Post → Email → Website → SEO → Delivery. On Delivery: excluded segments → Web Access toggle (Managed Audiences) → Summary splitting recipients per channel ("Email: 6 recipients", "Web: all free subscribers") → Preview/Send Test/Save Template/Schedule. Channels are separate tabs on the same content, reconciled at send time.
- **Intercom** `mobbin:7380bc5c-aee1-470d-afae-832b147f9e1b`: single Content-tab composer → From/Assign replies → Reply type (Text vs Email collector) → Sent-as (Badge/Snippet/full message) → Show first on (Web, iOS, Android dropdown) → push-notification-on-mobile toggle (off). Channel/platform/format settings are all inline controls in one panel, no separate screens per channel.
- **Kit** `mobbin:f722d4bb-07d8-409a-9b9b-4c12cbcfaec9`: single broadcast composer → audience filter builder → send-time field (defaults "Send now", editable) → Advanced options → "Publish to web" toggle (off) as an add-on channel beyond the default email send → Continue.
- **Substack** `mobbin:a7ebc4ec-996c-4383-9eff-adb43819f10c`: single mobile Publish modal → Audience (Publication, Who can view) → one combined "Notify subscribers (Email or push)" toggle, default on → "Send to all subscribers now".

## Distinctive

- beehiiv only: channel-specific tabs (Post/Email/Website/SEO) on one content object, reconciled in a per-channel recipient summary.
- Substack only: a single toggle bundles email and push together rather than exposing them as separate controls.
- Intercom only: platform targeting (Web/iOS/Android) alongside a chat-vs-email reply-format choice, in one panel.
- Kit only: "Publish to web" as an explicit opt-in channel layered on top of an implicit default (email).

## Counter-example candidate

`mobbin:7380bc5c-aee1-470d-afae-832b147f9e1b` (Intercom): the push-notification toggle sits below unrelated display-styling controls (Sent as: Badge/Snippet), and audience/recipient selection isn't visible on this screen at all — a course manager scanning for "which channel does this go out on" has to parse styling settings to find the one channel toggle.

## Weak references

None — all five images show the composer/publish screen relevant to channel choice.

## Take fixes

- `mobbin:0bc24c79-1906-420b-8c71-4c4c9fada060`: Single post composer combining in-app audience visibility (team-only vs client) with a separate scoped notify-list control (specific person, everyone I select, no one); no email/push channel shown.
- `mobbin:748e794e-69b4-4b84-81e8-eb81c5e32f85`: Delivery tab of a single post object with separate Post/Email/Website/SEO tabs; shows segment exclusion and a per-channel recipient summary (Email vs Web).
- `mobbin:7380bc5c-aee1-470d-afae-832b147f9e1b`: Content tab of one message composer: reply-type toggle (chat text vs email collector), Web/iOS/Android platform selector, and a mobile push toggle — no audience routing visible on this screen.
- `mobbin:f722d4bb-07d8-409a-9b9b-4c12cbcfaec9`: Single broadcast composer with an audience filter builder, an editable send-time field (defaults to now), and a "Publish to web" toggle as an additional channel beyond the default email send.
