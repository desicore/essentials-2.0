# Q5 — Capacity, sign-up and attendance model

**Aboard** (`mobbin:4fa0df58…`): self sign-up via single "Attend" button, toggles to "Attending" with a green check; attendee avatar appended to an "Attendees" list. No capacity, waitlist, or approval shown.

**Calendly** (`mobbin:733e9406…`): settings screen only — buffer time, minimum notice, daily-limit field ("events max per day"), time zone, start-time increments. This constrains host availability, not per-event attendee capacity; no sign-up or attendance step shown.

**Eventbrite** (`mobbin:c0b0ead0…`): capacity lives per ticket type (0/5 General, 0/20 Student) plus an overall "Event capacity 0/25" with an "Edit capacity" link. Ticket-tier capacity, not registrant-level; no waitlist UI visible.

**Luma** (`mobbin:68dc9ea7…`): guest list shows a hard cap ("0 guests / cap 1,000") and per-guest states — Invited, Pending Approval, Going — with a toast "Guest approved." This is approval-gated sign-up, and check-in is a separate "Check In Guests" action from "Guest List."

**Lyssna** (`mobbin:8a3407fe…`, flow, 5 imgs): host-side attendance marking. Sessions list shows a banner ("You have 1 session to mark attendance… auto-marked as completed after 5 days"), Actions menu offers Mark as Completed / Mark as No-show, a confirm modal, then the session row updates to "Completed." This is host-marked attendance with an automatic fallback, not attendee check-in.

**Partiful** (`refero:10204`, flow, 8 imgs): self sign-up as RSVP (Going/Maybe/Can't Go), with an explicit "Add a plus one" sub-flow (name + optional phone) before confirming. Capacity shown as "20/20 spots left" decrementing to "18/20" after RSVP — spots are consumed per invitee+plus-one, not a generic ticket pool.

**Posh** (`mobbin:4022cce6…`, flow, 3 imgs): host-side check-in on a private guestlist — toggling a guest's status from "Not Checked In" to "Checked In" via an action button, confirmed by toast. Host-marks-in-person attendance, distinct from Luma's approval and Lyssna's post-hoc completion marking.

**SavvyCal** (`refero:3371`, flow, 5 imgs): scheduled 1:1/group event; host can add attendees after the fact via "Invite a guest" (name + email) modal, then the invitee appears in the "Who" list. Attendance list is editable post-scheduling, no capacity or waitlist field visible.

**Understory** (`refero:12706`, flow, 4 imgs): capacity set as a discrete numeric field ("Capacity: 10" → edited to 12) on a date/location block, with a "No capacity limit" checkbox option. Editing capacity is decoupled from other event fields (room, language) in the wizard step.

**Distinctive:** Partiful ties capacity decrement to plus-ones, not just primary RSVPs — most granular seat accounting seen. Lyssna is the only reference showing automatic no-show/absent resolution after a deadline.

**Counter-example candidate:** none of the 9 shows both a capacity number AND a waitlist queue together — Understory/Eventbrite/Luma show capacity, Luma shows approval, but no ref demonstrates overflow-to-waitlist behavior. Flag as an evidence gap, not a claimed absence.

**Evidence gaps:** no reference shows self-service attendee check-in (only host-marked: Posh, Lyssna); no waitlist UI in this set; Calendly ref is about host daily limits, not event capacity — borderline relevant.
