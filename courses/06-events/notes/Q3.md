# Q3 — Recurrence and series editing (this / following / all)

## Per-product observed answer
- **Amie** (mobbin:68dd9778…, mobbin:1c7e609d…): "Repeat" modal sets frequency/days/end at creation; a separate "Update recurring event" dialog offers **two-option scope**: This event / All events.
- **Motion** (mobbin:1eb73c81…): Editing a recurring item opens "Update recurring event" with radio buttons **This event / All events** — two-option only, no "following" tier.
- **Zoom** (mobbin:b85c076b…): Recurrence is configured on the meeting-creation form (frequency, weekdays, end date/occurrence count). No edit-scope dialog is shown in this shot — creation only.
- **Skiff** (mobbin:d5d0e3c0…, 8-step flow): Shows "Repeats" toggle → frequency dropdown → "Customize recurring event" modal (repeat every/on/ends) → returns to calendar with new instances rendered. **No this/all/following scope dialog appears anywhere in the 8 frames**, despite the reference's "take" describing "edit scope selection."
- **Luma** (refero:1848, 7-step flow): Starts from a **single event**, then "Create Multi-Session Event" → manual session list or "Add Recurring Sessions" (cadence, number of weeks, weekday chips) → event becomes "+9 Sessions." This is the only reference showing **series creation from an existing single event**.
- **Microsoft Teams** (refero:9721): "New meeting" form has a recurrence control alongside date/time/attendees; only creation shown, no edit-scope dialog.
- **Understory** (refero:12705): "Repeating rule" modal (Repeats/Until) attached to date+location step; creation only, own dialog separate from base fields.
- **Acuity Scheduling** (refero:9872) — **counter-example**: rescheduling one appointment instance opens a plain reschedule panel (date/time picker) with no this/following/all choice at all — a single-instance-only edit pattern, useful contrast to the scope dialogs above.
- **Time2book** (mobbin:ee06623b…): "Add to schedule" panel has a "Repeat" dropdown ("Does not repeat…") at creation time only; no edit-scope evidence.

## Distinctive pattern
Two-option scope (this/all) is the dominant pattern (Amie, Motion). **No reference in this set shows a three-option "this / this and following / all" picker** — that finer granularity is not evidenced here, only inferred from general calendar-app knowledge.

## Counter-examples
1. Acuity (refero:9872) — single-instance-only edit, no series concept surfaced.
2. Skiff's take overclaims "edit scope selection" — the actual flow frames never show it; flag as evidence gap, not a confirmed pattern.

## Evidence gaps
- No three-way scope example found. No proof of conflict/attendee-notification behavior when scope is chosen. Skiff's claimed scope step is unverified in the captured frames.
